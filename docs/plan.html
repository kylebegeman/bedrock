Quark 0.7 Plan

Thirty-four locked items, in an order where every milestone leaves the test bed running something real. 0.7 runs the personal machine. 0.8 wires Loom. 0.9 opens the launchpad. 1.0 keeps the promise.

Item numbers refer to Quark Ideas. Dropped: 5, 13 and 17. Background is in the blueprint.

Ground rules

How the work runs

  • One binary. A milestone counts only when the test lane (36) has proven it on a machine wiped and rebuilt for the purpose.
  • Python Ophelia is frozen at 0.6.x. It gets only the fixes needed to keep today's production up until moving day.
  • Every operation leaves a receipt. Secrets never appear in arguments, logs, receipts or backups.
  • The old machines keep running until each replacement is live and checked. Kyle runs the permanent deletes and the DNS switches; the plan says when.

Loom

What changes on Loom's side

In 0.7

  • packages/core-provisioning keeps connect, host-key trust, the DNS check and the owner code; its prepare, build, manifest and deploy steps become calls to quark.
  • deploy/ophelia/ (58 files, about 12,000 lines) is deleted after moving day, along with the Ophelia pin in toolchain.json.
  • The Runner is declared as a privileged workload in the Loom manifest.
  • CORE-05, the fresh start, is moving day.

In 0.8

  • CORE-03 (set up a new Core from the app) and CORE-04 (upgrade, rollback, status and backups from the app) build on Quark's API and the enrollment link.
  • A Fleet view: machines, apps, health, deploys, backups, drills, alerts, logs, approvals.
  • Alerts become push notifications.
  • Two Core endpoints for Loom sign-in on routes (35), and approval records for agent-run operations (34).
Risks

What could go wrong, and the answer

  • A lot of build before the payoff. Each milestone leaves something live on the test bed, and the old machines stay up until moving day, so nothing is at risk while it's built.
  • Quark owns Caddy's whole config, so every site on a machine must be a Quark app. On these two machines that's true by design.
  • Postgres major upgrades. 0.7 answers with dump and restore through the backup path; in-place upgrades come later.
  • The Runner needs privileges. Isolation (28) lands before previews from anyone else's branches, which is 0.9, not before your own.
  • The Loom link (32) is the largest Loom-side item. 0.7 doesn't wait on it; alerts go by email until it exists.
